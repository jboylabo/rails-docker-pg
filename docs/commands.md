# Docker コマンド解説

ここでのコマンドは、このリポジトリで次の形に限定します。

```bash
docker compose -f compose.yaml <サブコマンド>
```

作業ディレクトリは `compose.yaml` がある場所です。プロジェクト名は `rails8-task-learning` です。他の Compose プロジェクトは操作しません。

各コマンドは次の順で読みます。

1. コマンドの意味
2. オプションの意味
3. 使う場面
4. 実行すると何が起きるか
5. 既存 Docker 環境への影響
6. 初心者が注意するポイント

## オプション辞典

### exec

動いているコンテナの中で、追加のプロセスを実行します。コンテナは新しく作りません。

### -it

`-i` と `-t` を同時に付けた書き方です。対話入力と端末表示を有効にします。

### -i

標準入力を開いたままにします。キーボード入力をコンテナへ渡せます。

### -t

擬似端末を割り当てます。`bash` や `bin/rails console` のように画面を使うコマンドで使います。

### -d

デタッチです。起動したあとに端末を占有せず、バックグラウンドで動かし続けます。

### --rm

`docker compose run` で作った一時コンテナを、コマンド終了後に削除します。このプロジェクトの一時コンテナだけが対象です。Volume や他プロジェクトは消しません。

### --build

`up` の前に、Dockerfile から Image を作り直します。Gemfile を変えたあとに使います。

### --no-cache

Dockerfile の層キャッシュを使わず、RUN からやり直します。キャッシュが古くて原因が分からないときに限って使います。時間とネットワークを使います。

### -f

Compose ファイルのパスを指定します。この学習では `-f compose.yaml` と書き、意図しないファイルを読まないようにします。

### -p

二つの意味があります。`docker compose` の `-p` はプロジェクト名です。このファイルは `name:` で `rails8-task-learning` を固定しているので、通常は付けません。`ports` の `-p`（`docker run -p`）はホストとコンテナのポート対応です。PostgreSQL の 5432 はホストへ公開していません。

### -v

`docker run` ではマウント指定です。`docker compose down -v` の `-v` は Volume 削除です。意味が違うので、down に `-v` は付けません。

## docker exec -it container_name bash

1. 指定したコンテナの中で bash を開きます。
2. `-it` はキーボード入力と端末表示です。
3. 起動中のコンテナを調べるときに使います。
4. そのコンテナの中にシェルができます。終了してもコンテナは止まりません。
5. 名前を間違えると、仕事用コンテナの中へ入れます。この学習では使いません。
6. コンテナ名を手で書かないでください。次の Compose 版を使います。

## docker compose exec web bash

1. このプロジェクトの web コンテナで bash を開きます。
2. `exec` は起動中のサービスに入る、という意味です。`-it` が必要なら `docker compose exec -it web bash` と書きます。
3. Rails のファイルをコンテナ側から確認するときに使います。
4. web コンテナの中にシェルができます。
5. 対象はこのプロジェクトの web だけです。他のコンテナは変わりません。
6. web が止まっていると失敗します。先に `up -d` で起動します。

## docker compose run --rm web bash

1. web の定義で一時コンテナを作り、bash を起動します。
2. `--rm` は終了後にその一時コンテナを削除します。
3. web が止まっていても、一度だけコマンドを試すときに使います。
4. 別コンテナが立ち上がります。db に `depends_on` があるため、設定によっては db も起動します。終了後、一時 web コンテナは消えます。
5. このプロジェクトの一時コンテナだけを削除します。他プロジェクトのコンテナ、Volume、Network は削除しません。
6. すでに web が動いているなら、同じ作業は `exec` の方が軽く安全です。`run` は増やす、`exec` は入る、と覚えます。

## exec と run の違い

`exec` は動いているコンテナに相乗りします。プロセスが増えるだけで、コンテナは増えません。`run` はサービス定義から別のコンテナを起動します。マイグレーションを一度だけ流す、起動前にコマンドを試す、といった場面が `run` です。普段の `bin/rails console` や `bin/rails test` は、起動済みの web に対する `exec` を使います。

## docker compose up -d

1. このプロジェクトの db と web を起動します。
2. `-d` はバックグラウンド実行です。
3. 開発を始めるときに使います。
4. 専用 Network と Volume が無ければ作り、db の healthcheck が成功してから web を起動します。Rails はホストの 13000 番から届きます。PostgreSQL の 5432 はホストに開きません。
5. このプロジェクトのコンテナだけを起動します。他のコンテナは開始も停止もしません。
6. 13000 番が使用中なら、使っているプロセスを止めずに `.env` の `WEB_PORT` を空いている番号へ変えます。

## docker compose up -d --build

1. Image を作り直してから、バックグラウンドで起動します。
2. `--build` は起動前のビルドです。`-d` はバックグラウンドです。
3. Dockerfile や Gemfile を変えたあとに使います。
4. web の Image を再ビルドし、コンテナを作り直します。ソースの bind mount はそのままです。
5. ビルド対象はこのプロジェクトの web です。他の Image は削除しません。
6. コードだけの変更なら再ビルドは不要です。`app` はマウントされているので、保存すれば Rails が読み込みます。gem を足したときだけビルドします。

## docker compose build --no-cache web

1. web の Image を、キャッシュなしで作ります。
2. `--no-cache` は層の再利用をやめます。`web` はサービス名です。
3. キャッシュが原因で古いパッケージが残っているときに使います。
4. apt と bundle install を最初から実行します。コンテナは起動しません。
5. この Dockerfile のビルドだけです。`docker builder prune` のような全体削除はしません。
6. 時間がかかります。通常の変更は `--no-cache` なしの build で足ります。

## docker compose logs -f web

1. web のログを追って表示します。
2. `-f` は新しい出力を待ち続けます。`web` はサービス名です。
3. 起動エラーや SQL を見るときに使います。
4. 端末にログが出続けます。Ctrl-C で表示だけ止まり、コンテナは動き続けます。
5. このプロジェクトの web ログだけです。他のコンテナのログは出ません。
6. ログ確認でコンテナを再起動する必要はありません。

## docker compose ps

1. このプロジェクトのコンテナ一覧を出します。
2. 追加オプションはありません。
3. 起動できたか、ポートは何番か、db は healthy かを見るときに使います。
4. 状態を表示するだけで、起動や停止はしません。
5. このプロジェクト以外は表示しません。全体を見たいときも、止めたり消したりはしません。
6. 名前が `rails8-task-learning` で始まっていることを確認してから、次の操作をします。

## docker compose down

1. このプロジェクトのコンテナを止め、Compose が作った既定の Network を外します。
2. ここには `-v` を付けません。
3. 学習を終えて Rails と PostgreSQL を止めたいときに使います。
4. web と db が停止します。Volume `postgres_data` は残るので、次の `up -d` でデータは戻ります。
5. 他プロジェクトのコンテナ、Image、Volume、Network は停止も削除もしません。
6. `docker compose down -v`、`docker system prune`、`docker volume rm` は実行しません。データを消す操作と、全体を掃除する操作は別物です。
